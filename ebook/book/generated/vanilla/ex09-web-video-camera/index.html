ex09 — Web video camera

Track: vanilla · Project: web-app · Port: 5174

cd web-app
vp install   # first time
vp dev
# open http://localhost:5174/ex09-web-video-camera/

Source: web-app/ex09-web-video-camera/README.md

Goal. Show a live camera preview: request video with getUserMedia, attach the MediaStream to a <video> element through srcObject, read the real resolution from the track, and release the camera cleanly with track.stop().

This lab reuses the capture permission pattern from ex07 — Web Audio mic for video instead of audio. It needs no AudioContext. It is the last browser-media lab before hardware links starting with ex10 — Web Serial.

Learning outcomes

After this lab you should be able to:

  1. Request camera access with getUserMedia({ video: … }) and handle common rejections.
  2. Explain why a secure context and user gesture are required, parallel to ex07.
  3. Attach a stream with video.srcObject and explain why autoplay, muted, and playsinline matter.
  4. Read capture settings from MediaStreamTrack.getSettings().
  5. Distinguish a constraint (what you ask for) from a setting (what you got).
  6. Turn the camera off with track.stop() and mirror the preview with CSS only.
  7. State when the AudioContext gesture rule would apply if you added audio (ex07/ex08).

Theory

Three browser rules (media track)

When you add mic, speaker, or camera features, three policies often overlap:

RuleApplies here?Detail
Capture permission (getUserMedia)YesSecure context; start from Start camera click
Video autoplayYes<video> needs muted (and usually a gesture) to play inline
AudioContext autoplayNo ( audio: false )If you add audio, create/resume() context in a click (ex07, ex08)

ex10 adds a fourth pattern for hardware: Web Serial port picker on secure origin + user gesture — no camera involved.

Permission: same API as the mic

getUserMedia backs both microphone and camera. You pass constraints; the browser prompts; the promise resolves with a MediaStream or rejects.

RequirementWhy
Secure context (HTTPS or localhost)navigator.mediaDevices missing on plain HTTP
User consentBrowser shows recording indicator while tracks are live
Click-driven startPrompts tied to intent — not on page load
Available cameraOtherwise NotFoundError

Typical rejections (err.name):

err.nameMeaning
NotAllowedErrorDenied or permissions policy (iframe without camera)
NotFoundErrorNo camera device
NotReadableErrorCamera in use elsewhere
OverconstrainedErrorAn exact constraint cannot be met

Constraints vs settings

getUserMedia({ video: { facingMode: "user" }, audio: false }) expresses constraints.

FormMeaningFailure
video: trueAny cameraOnly if none exist
{ facingMode: "user" }Prefer front cameraIdeal — may fall back
{ width: { ideal: 1280 } }Prefer sizeClosest mode
{ width: { exact: 1280 } }Must matchOverconstrainedError

After success, track.getSettings() reports actual width, height, frameRate, deviceId, etc. The lab falls back to video.videoWidth / videoHeight when needed.

srcObject, autoplay, and inline playback

  • srcObject accepts a MediaStream object. video.src = "…" is for URLs, not live capture.
  • muted — required for autoplay without extra user steps in most browsers.
  • playsinline — prevents iOS from forcing fullscreen on play.
  • await video.play() after Start camera — runs in the gesture chain started by the click.

If you later set audio: true, follow ex07: build the Web Audio graph in the click handler and resume() the context. Do not route mic to speakers without headphones.

Why track.stop() matters

ActionCamera light?
video.pause() or remove elementOften stays on
stream = null onlyStays on until GC
track.stop() on each trackTurns off — releases device
track.enabled = falseMay stay on (black frames)

stopCamera() stops every track, clears srcObject, and toggles UI off.

Mirroring is presentation only

CSS transform: scaleX(-1) mirrors the preview like a selfie mirror. Frames in the stream are not flipped. Canvas capture or upload needs an explicit flip if you want non-mirrored text.

Run

Needs HTTPS or localhost, a camera, and allow in the prompt. Close other apps that hold the camera. Reset site permission if you blocked it earlier.

Walkthrough (main.ts)

  1. State — single stream: MediaStream | null (live flag).
  2. startCamera() — guard double start; disable buttons; getUserMedia with facingMode: "user"; assign srcObject; await play(); read getSettings() for resolution; setLive(true).
  3. catch — error in readout; stopCamera() for clean idle.
  4. stopCamera() — track.stop() all tracks; clear srcObject; reset UI.
  5. Listeners — Start only from click (void startCamera()).

Experiment: try { width: { ideal: 640 }, height: { ideal: 480 } }, then exact: 4000 to see OverconstrainedError.

Checklist

  • Start camera asks for permission and shows a live image
  • Preview is mirrored (front-camera style)
  • Readout shows resolution when live
  • Stop turns camera off (indicator light out), placeholder returns
  • Start → Stop → Start works
  • Denying permission shows error: and leaves Start enabled

Common pitfalls

SymptomLikely cause
getUserMedia of undefinedInsecure origin
Prompt never appearsBlocked site or iframe without camera permission
Black previewWrong src, missing srcObject, or play() failed
play() NotAllowedErrorUnmuted video without gesture — keep muted
iOS fullscreenMissing playsinline
Camera light after StopTracks not stopped
NotReadableErrorAnother tab or app owns the camera
Backwards text in capturesCSS mirror only on preview — flip captures if needed
Wrong camera on phone"user" is front — use "environment" for rear
