Source: web-app/ex06-canvas-draw/README.md

Goal. Draw the same pointer sketch as ex05 — SVG draw, but into a <canvas> with the 2D context: beginPath, moveTo, lineTo, stroke. Learn what changes when you switch from a scene graph to a bitmap, and why devicePixelRatio matters on HiDPI displays.

Learning outcomes

After this lab you should be able to:

  1. Obtain a CanvasRenderingContext2D with getContext("2d") and handle a null result.
  2. Draw line segments incrementally with beginPath / moveTo / lineTo / stroke.
  3. Explain the difference between canvas CSS size and bitmap size and size both for HiDPI.
  4. Use setTransform(dpr, 0, 0, dpr, 0, 0) so drawing code works in CSS pixels.
  5. Clear with clearRect and explain why assigning canvas.width / height resets the bitmap.
  6. Compare canvas (immediate, raster) with SVG (retained, vector) and choose between them.

Theory

Immediate mode: paint and forget

A canvas is one rectangle of pixels. Each call such as stroke() paints pixels and returns. The canvas keeps no list of shapes; there is nothing to select, restyle, or delete later except by repainting the area or keeping your own point history.

Contrast ex05: there every stroke is a <polyline> you can delete individually. Here, Clear only erases pixels — the lab does not store past strokes for undo.

Two sizes: CSS vs bitmap

PropertyMeaningSet in this lab
canvas.style.width/heightSize on the page (CSS pixels)cssW × 260
canvas.width/heightBitmap pixel dimensionscssW×dpr × 260×dpr
devicePixelRatio (dpr)Device pixels per CSS pixelRead in sizeCanvas()

If you leave the bitmap at the default 300×150 and stretch it with CSS, the browser scales the bitmap up and lines look blurry. With dpr = 2, you need twice the pixels in each direction. ctx.setTransform(dpr, 0, 0, dpr, 0, 0) lets drawing code use CSS-pixel coordinates, so canvasPoint() can be plain clientX - rect.left.

Setting canvas.width or canvas.height (even to the same value) resets the bitmap and the context state (lineWidth, lineCap, transform). That is why sizeCanvas() re-applies style and why this lab clears the drawing on window resize.

The 2D path API

CallEffect
ctx.strokeStyle = colorColor for the next stroke()
ctx.beginPath()Start a new empty path
ctx.moveTo(x, y)Pen up, jump to a point
ctx.lineTo(x, y)Add a segment from the current point
ctx.stroke()Paint the path outline into the bitmap
ctx.clearRect(x, y, w, h)Set a rectangle to transparent

In extendStroke, each move draws one short segment then starts a fresh path at the new point so later stroke() calls do not re-paint old segments.

Walkthrough (main.ts)

  1. Context setup — getContext("2d") can return null; the lab throws a clear error instead of asserting.
  2. sizeCanvas() — dpr, wrap width, CSS size, bitmap size, setTransform, line style. Runs at startup and on every resize; clearing on resize is intentional.
  3. canvasPoint(ev) — clientX - rect.left only; the transform handles dpr. Compare with svgPoint in ex05 (viewBox scaling).
  4. beginStroke — strokeStyle, path start at pointer.
  5. extendStroke — lineTo + stroke(), then new path so old segments are not re-stroked.
  6. Clear — clearRect(0, 0, clientWidth, clientHeight) in CSS-pixel space.

Experiment: change zoom or move to a HiDPI monitor; readout should show bitmap size ≈ CSS size × dpr (for example 1280×520 when dpr is 2).

Checklist

  • Drag draws a colored stroke
  • Color swatches change the next stroke
  • Clear wipes the bitmap and resets strokes=0
  • DevTools shows one <canvas> with no stroke child nodes (unlike SVG)
  • Readout shows bitmap size equal to CSS size × dpr
  • Lines look sharp on a HiDPI display (not blurry)

Common pitfalls

SymptomLikely cause
Blurry lines on Retina / HiDPIBitmap size equals CSS size without dpr scaling
Line lands away from the cursorCSS and bitmap size mismatch without transform
Lines vanish after resizeSetting canvas.width/height resets the bitmap
Line width or color reverts after resizeContext state reset — re-apply in sizeCanvas()
Whole path repaints on each segmentForgot beginPath() after stroke()
getContext returns nullUnsupported or context already taken
Page scrolls while drawing on touchMissing touch-action: none
Cannot select a stroke in DevToolsCanvas has no scene graph — use SVG (ex05) or store points
