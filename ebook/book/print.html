Goal. See how a browser page is built from three cooperating files (HTML, CSS, TypeScript) and make your first interactive change: a button that updates a counter.

This is the first lab of the vanilla track. There is no React, no Tailwind, and no board yet — only the browser, the DOM, and one click handler.

Learning outcomes

After this lab you should be able to:

  1. Explain the role of HTML (structure), CSS (look), and TypeScript (behavior) in one sentence each.
  2. Describe what the DOM is and why TypeScript talks to it instead of the HTML file on disk.
  3. Find an element with document.getElementById and narrow its type with instanceof.
  4. Register a click listener with addEventListener and update text with textContent.
  5. Explain why the page must be served over http:// (via vp dev) and not opened as a file:// document.
  6. Make three small edits (heading, --accent, click step) and see Vite+ hot update the page.

Theory

Three languages, three jobs

Appearancestyles.cssHow does it look?--accent, card layout
Behaviormain.tsWhat happens when I act?Count clicks, write the number into text

The id attribute is the hook that lets behavior find structure. You can change color in CSS without touching logic, or change logic without touching markup.

From files to pixels

The browser parses HTML into a tree of objects in memory — the DOM (Document Object Model). CSS rules match those nodes to produce computed styles. JavaScript (compiled from TypeScript) reads and writes the live DOM; the browser repaints.

TypeScript never edits index.html on disk. Reload the tab and the tree is rebuilt from the file, so the counter returns to 0.

Why TypeScript?

TypeScript is JavaScript plus types checked by the IDE and tsc. document.getElementById returns HTMLElement | null. Types force you to handle a missing element before use.

ExpressionTypeWhy it matters
document.getElementById("count")HTMLElement | nullMisspelled id yields null
countEl instanceof HTMLElementboolean (type guard)After the check, TypeScript knows it is not null
bumpBtn instanceof HTMLButtonElementboolean (type guard)Button-specific properties
let clicks = 0numberAssigning a string later is a type error

Vite+ compiles .ts on the fly during vp dev — no separate build step while learning.

Events and state

The browser raises an event when something happens (click, key, pointer). You attach a listener — a function — to an element; the browser calls it once per event.

ConceptIn this lab
Event targetbumpBtn
Event type"click"
ListenerArrow function that increments clicks
StateModule variable let clicks = 0
Visible outputcountEl.textContent = String(clicks)

textContent expects a string and treats the value as plain text, never as HTML — the safe choice for numbers and names.

Why type="module" and why not file://

<script type="module" src="./main.ts"> loads code as an ES module. Modules are deferred (they run after the document is parsed) and are fetched with HTTP rules. Opening index.html by double-click uses file://, where the browser blocks module loading and cannot compile .ts. Symptom: the page renders, but clicking does nothing and the counter stays at 0.

vp dev serves files over HTTP (port 5174) and compiles TypeScript for the browser.

Goal. Build UI at runtime with TypeScript DOM APIs — createElement, append, textContent, remove — instead of finding elements that already exist in the HTML.

Learning outcomes

After this lab you should be able to:

  1. Create an element with document.createElement and configure it with textContent, className, type, dataset, and setAttribute.
  2. Attach nodes with append and detach them with remove or replaceChildren.
  3. Explain the difference between a node in memory and a node in the live DOM.
  4. Attach a listener to a node you just created and use a closure so each Remove button knows its row.
  5. Keep a status line in sync by reading list.children.length.
  6. Explain why textContent is safer than innerHTML for untrusted or plain text.

Theory

The DOM is a tree you can edit

Every element is a node with a parent and children. index.html is a thin shell: one empty <div id="mount" class="card">. All interactive UI is built in main.ts and attached under #mount.

Each list row is a small subtree: li.item containing a label span and a Remove button. See the Diagrams section for the full mount layout.

Closures: each Remove knows its row

Inside addItem(), the Remove button’s click listener calls li.remove(). The arrow function closes over the local li, so every button removes its own row after addItem() returns — no ids or event delegation required at this level.

textContent versus innerHTML

The hint in main.ts mentions <li> and <ul> as literal text:

hint.textContent = "Each click builds an <li> in memory, then appends it to the <ul>.";

Because textContent does not parse HTML, angle brackets appear on screen as written. With innerHTML, the browser would try to interpret markup. Prefer textContent whenever the value is not trusted HTML.

Goal. Drive live CSS from TypeScript — update numbers on a timer (setInterval), then assign element.style.* (color, size, position, rotation, radius, opacity) so a box moves, spins, and changes color.

ex01 created nodes. This lab restyles one node many times per second.

Learning outcomes

After this lab you should be able to:

  1. Separate state (a plain object of numbers) from presentation (writing those numbers into element.style).
  2. Use setInterval and clearInterval to start and stop a timer safely.
  3. Write CSS values from TypeScript with template strings (`${n}px`, hsla(...), translate(...) rotate(...)).
  4. Explain why transform uses translate(...) then rotate(...) to keep the box centered while spinning.
  5. Read layout sizes with clientWidth / clientHeight to scale motion to the stage.
  6. Edit one formula in tick() and predict the visual change.

Theory

Inline styles override stylesheet defaults

styles.css defines the default look (.stage, .shape). Assigning el.style.someProperty = value writes an inline style, which wins over normal stylesheet rules — the simplest way for code to drive visuals.

CSS propertyJS propertyValue in this lab
width, heightstyle.width, .height`${size}px`
background-colorstyle.backgroundColor`hsla(${hue}, 70%, 55%, ${alpha})`
border-radiusstyle.borderRadius`${radius}px`
left, topstyle.left, .topPixel position inside the stage
transformstyle.transformtranslate(...) rotate(...)

CSS names with hyphens become camelCase in JavaScript. Numbers need units — "48px" is valid; bare 48 is not.

State, then paint

The lab keeps one object, params, with all animated numbers:

FieldMeaningTypical range in this lab
tMotion clock (+0.05 per tick)0 upward
hueColor angle (degrees)0–360 (wraps with % 360)
sizeSquare side length (px)about 40–68
x, yBox center inside the stagefrom sin / cos of t
rotRotation (degrees)t * 55
radiusCorner radius (px)about 8–28
alphaOpacity (0–1)about 0.55–0.95
  • tick() updates numbers from formulas.
  • applyStyle(params) writes them into the DOM.

That split is the seed of every UI framework: state in, DOM out. Reset t calls tick() once; Pause stops the timer without losing params.

Smooth motion from sine and cosine

Math.sin(t) swings between -1 and 1. Multiplying by an amplitude and adding a center gives a back-and-forth path:

params.x = stage.clientWidth * 0.5 + Math.sin(params.t) * (stage.clientWidth * 0.32);

Different speeds for x (t) and y (t * 0.85) trace a loop. The pattern 0.5 + 0.5 * Math.sin(...) maps sine from [-1, 1] to [0, 1] for size, radius, and alpha.

Positioning and centering

.stage is position: relative; .shape is position: absolute, so left / top are from the stage corner. The code shifts by half the size in transform so (x, y) is the center of the box. Order matters: translate first, then rotate so rotation is around the shape center.

Timers and hot reload

TICK_MS = 32 is ~31 fps. Intervals are not exact — tabs in the background get throttled. Later labs use requestAnimationFrame for display-synced drawing.

start() and pause() guard on timer so two overlapping intervals cannot double the animation speed.

During vp dev, saving main.ts replaces the module. Without cleanup, the old interval would keep running:

  import.meta.hot.dispose(() => {
    pause();

Theory

Retained mode: the drawing is the DOM

An <svg> is part of the document tree. Each shape (<polyline>, <circle>, <path>) is an element with attributes, can be styled by CSS, receives events, and shows up in DevTools. The browser keeps the scene description and re-rasterizes it whenever needed (resize, zoom, print). You describe what exists; the browser decides how to paint it.

Why createElementNS

HTML and SVG are different XML vocabularies. document.createElement("polyline") creates an HTML unknown element that the SVG renderer ignores — it never appears. The SVG namespace tells the DOM which vocabulary the tag belongs to.

CallNamespaceResult
document.createElement("polyline")HTMLInert unknown element, nothing drawn
document.createElementNS(SVG_NS, "polyline")http://www.w3.org/2000/svgReal SVG shape
el.setAttribute("points", "…")—Works on SVG elements (attribute, not property)

Coordinate systems

The pad is declared as viewBox="0 0 640 260" with preserveAspectRatio="none". The viewBox is the internal coordinate space; the element’s on-screen size comes from CSS and can be anything. svgPoint() maps screen pixels into viewBox units (see the coordinate diagram under Diagrams).

Because the stroke is stored in viewBox units, resizing the window scales the drawing with the pad — no redraw code needed. That is a core SVG advantage over a fixed bitmap (ex06).

setPointerCapture routes later events to the pad even if the pointer leaves it. touch-action: none in styles.css stops touch screens from scrolling instead of drawing. The same pointer pattern is reused in ex06 with no API change — only the target of drawing changes (DOM vs canvas context).

Theory

Immediate mode: paint and forget

A canvas is one rectangle of pixels. Each call such as stroke() paints pixels and returns. The canvas keeps no list of shapes; there is nothing to select, restyle, or delete later except by repainting the area or keeping your own point history.

Contrast ex05: there every stroke is a <polyline> you can delete individually. Here, Clear only erases pixels — the lab does not store past strokes for undo.

Two sizes: CSS vs bitmap

canvas.width/heightBitmap pixel dimensionscssW×dpr × 260×dpr
devicePixelRatio (dpr)Device pixels per CSS pixelRead in sizeCanvas()

If you leave the bitmap at the default 300×150 and stretch it with CSS, the browser scales the bitmap up and lines look blurry. With dpr = 2, you need twice the pixels in each direction. ctx.setTransform(dpr, 0, 0, dpr, 0, 0) lets drawing code use CSS-pixel coordinates, so canvasPoint() can be plain clientX - rect.left.

Setting canvas.width or canvas.height (even to the same value) resets the bitmap and the context state (lineWidth, lineCap, transform). That is why sizeCanvas() re-applies style and why this lab clears the drawing on window resize.

Theory

What Web Serial is

Web Serial is a browser API (navigator.serial) that lets a web page talk to a USB serial device without a native app. The page:

  1. Asks the user to pick a port (requestPort()).
  2. Opens it at a baud rate (open({ baudRate })).
  3. Reads and writes raw Uint8Array chunks on streams.

Cronos boards appear as a USB serial (CDC / USB-Serial/JTAG) device. The firmware speaks a framed binary protocol on that pipe. The browser never sees “BoardInfo” as text — it sees bytes. @sdk turns those bytes into typed frames.

The page does not speak USB descriptors itself. It only sees a serial port of bytes. Framing happens in software:

Frame sketch (conceptual — see sdk/wire/frame.ts):

  0x00  COBS(msgType | seq | len | payload | crc16)  0x00
   ^                                                  ^
   delimiters                                  delimiters
LayerJob
USB serialMove opaque bytes

CRC16Reject corruption

You do not hand-parse COBS in this lab. BoardSession feeds the read loop into FrameDecoder; your code only handles already-decoded frames.

writeAcked details

  • Default timeout: 2500 ms.
  • Matches inbound MSG_CMD_ACK (0x27) on msgType + seq.
  • A newer writeAcked rejects any previous pending wait ("Replaced by a newer command.").
  • Timeout rejects with a hint about serial-bridge firmware.

State sketch: idle → picking → open (then ready=true after settle); picker cancel returns to idle; disconnect() always returns to idle.
