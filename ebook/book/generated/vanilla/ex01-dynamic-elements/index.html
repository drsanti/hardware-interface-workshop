Source: web-app/ex01-dynamic-elements/README.md

Goal. Build UI at runtime with TypeScript DOM APIs — createElement, append, textContent, remove — instead of finding elements that already exist in the HTML.

ex00 found nodes. This lab creates them, wires listeners, and deletes them again.

Learning outcomes

After this lab you should be able to:

  1. Create an element with document.createElement and configure it with textContent, className, type, dataset, and setAttribute.
  2. Attach nodes with append and detach them with remove or replaceChildren.
  3. Explain the difference between a node in memory and a node in the live DOM.
  4. Attach a listener to a node you just created and use a closure so each Remove button knows its row.
  5. Keep a status line in sync by reading list.children.length.
  6. Explain why textContent is safer than innerHTML for untrusted or plain text.

Theory

The DOM is a tree you can edit

Every element is a node with a parent and children. index.html is a thin shell: one empty <div id="mount" class="card">. All interactive UI is built in main.ts and attached under #mount.

Each list row is a small subtree: li.item containing a label span and a Remove button. See the Diagrams section for the full mount layout.

Adding and removing

OperationEffectWhere
parent.append(a, b, c)Add children at the endtoolbar.append(addBtn, …)
li.remove()Remove this node from its parentRemove button listener
list.replaceChildren()Remove all children (no args = empty list)Clear button
list.children.lengthCount of child elementsrefreshStatus()

append on a node already in the document moves it. mount.append(...) runs once at the end, after every part is ready.

Closures: each Remove knows its row

Inside addItem(), the Remove button’s click listener calls li.remove(). The arrow function closes over the local li, so every button removes its own row after addItem() returns — no ids or event delegation required at this level.

textContent versus innerHTML

The hint in main.ts mentions <li> and <ul> as literal text:

hint.textContent = "Each click builds an <li> in memory, then appends it to the <ul>.";

Because textContent does not parse HTML, angle brackets appear on screen as written. With innerHTML, the browser would try to interpret markup. Prefer textContent whenever the value is not trusted HTML.

Walkthrough (main.ts)

  1. Mount point — getElementById("mount") plus an instanceof guard (same pattern as ex00).
  2. Constants and state — LABELS and nextId at module scope.
  3. Static parts built once — title, hint, toolbar, addBtn, clearBtn, list, status. toolbar.append(addBtn, clearBtn) groups buttons before anything is on screen.
  4. refreshStatus() — reads list.children.length; called from add, remove, and clear.
  5. addItem() — create li, span, button, attach Remove listener, list.append(li).
  6. Toolbar listeners — Add calls addItem; Clear calls list.replaceChildren().
  7. Final assembly — mount.append(title, hint, toolbar, list, status) and initial refreshStatus().

Ask while reading: which nodes exist before the first click, and which are created later?

Checklist

  • Add item appends a new <li>
  • Remove deletes that row only
  • Clear empties the list
  • The status line always matches the number of rows
  • You changed a label string or class in main.ts once

Common pitfalls

SymptomLikely causeFix
New element never appearsCreated but never attachedCall parent.append(node)
Element appears once, then disappearsRe-appended the same node (it moves)Create a new node per row
Every Remove deletes the last rowShared outer variable instead of per-row liDeclare li inside addItem()
Status shows stale countForgot refreshStatus() after a changeCall it from add, remove, and clear
Button submits or reloads a formDefault type="submit"Set button.type = "button"
<li> text renders as an elementUsed innerHTML for plain textUse textContent
dataset.id = 3 fails to type-checkdataset values must be stringsUse String(id)
