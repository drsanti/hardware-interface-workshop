ex03 — Form events

Track: vanilla · Project: web-app · Port: 5174

cd web-app
vp install   # first time

Source: web-app/ex03-form-events/README.md

Goal. Handle form events in TypeScript — input for live feedback, change for committed values, and submit with preventDefault() plus FormData so data is processed on the page without a reload.

This lab does not use keydown or pointer events yet; those arrive in ex04.

Learning outcomes

After this lab you should be able to:

  1. Choose between input, change, and submit for a given interaction and explain when each fires.
  2. Read control values with .value, .checked, and .selectedOptions.
  3. Stop default form navigation with event.preventDefault().
  4. Collect a form with new FormData(form) and narrow FormDataEntryValue | null to a string.
  5. Explain why an unchecked checkbox is absent from FormData and a checked one is "on" by default.
  6. Validate in TypeScript (trim, empty check) and give feedback via status and log.
  7. Read a lab split into ui.ts (DOM helpers) and main.ts (events and logic).

Theory

Three events, three moments

EventFires whenTypical useIn this lab
inputValue changes (every keystroke, slider move)Live preview#name updates preview each key
changeValue committed (select, checkbox; text on blur)Settings, choices#role, #notify
submitForm submitted (button click or Enter in a field)Save as a wholeSave badge adds a row

For a text field, input fires many times; change fires once when the field loses focus after a modification. For checkbox and select, change fires immediately on the user’s choice — why this lab uses change there but input on the name field.

Reading control values

ControlPropertyTypeIn main.ts
<input type="text">.valuestringui.name.value.trim()
<select>.value, .selectedOptionsstring, collectionselectedOptions[0]?.textContent for label
<input type=checkbox>.checkedbooleanui.notify.checked in preview
<form>new FormData(form)FormDataSubmit handler

value is what the program sends ("ta"); visible text is what the user reads ("TA"). roleLabel() uses visible text for the preview.

Submit and preventDefault

By default, submitting navigates away and destroys in-memory state. A single-page lab must cancel that:

ui.form.addEventListener("submit", (ev) => {
  ev.preventDefault();
  // ... read FormData and update the DOM ...
});

Listen on the form’s submit, not only the button’s click, so Enter in the text field uses the same path (implicit submission).

FormData and types

new FormData(form) collects every named control (name, role, notify in HTML).

CallReturnsGuard in code
data.get("name")string | File | nullNarrow with typeof === "string"
data.get("role")string | File | nullFall back to ""
data.get("notify")"on" or nullUnchecked checkbox not included

So notify is data.get("notify") === "on", not a "true" string.

Validation without browser popups

The form has novalidate, which disables built-in validation UI even though the input may have required. The lab validates itself:

  1. trim() the name so spaces-only is empty.
  2. If empty: status message, log rejected submit, ui.name.focus(), return.
  3. If valid: add row, clear field, refresh preview, refocus.

Split: ui.ts vs main.ts

FileResponsibilityRead it?
ui.tsLook up elements once (requireEl); paint text/listsSkim
main.tsaddEventListener, validation, event semanticsRead carefully

requireEl(id, HTMLInputElement) throws if missing or wrong type. Exporting ui lets main.ts write ui.name instead of repeating lookups. logEvent caps the log at 12 entries by dropping the oldest.

Walkthrough (main.ts)

  1. Imports — ui and paint helpers from ./ui. No listeners in ui.ts.
  2. roleLabel() — selectedOptions[0]?.textContent, fallback to value.
  3. refreshPreview() — one function builds preview text; every handler calls it.
  4. ui.name input — preview, status, log per keystroke.
  5. ui.role and ui.notify change — same trio, on commit.
  6. ui.form submit — preventDefault, FormData, type narrowing, empty-name branch, saved branch, reset and refocus.

Skim index.html for name attributes (must match data.get keys) and ui.ts for requireEl.

Experiment: type quickly, then Tab. You should see one input log line per keystroke and no change on the name field — only select and checkbox use change.

Checklist

  • Typing updates the preview on every key (input)
  • Changing role / checkbox logs change
  • Save badge adds a row without reloading
  • Empty name shows a status message (no navigation)
  • Enter in the name field also saves
  • You can explain why notify is missing from FormData when unchecked

TermMeaning
